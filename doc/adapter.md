# Преобразователь

Данный модуль является преобразователем (переходником) интерфейса Valid-Credit в интерфейс Valid-Ready

## Теория

### Valid-Ready

Простой интерфейс взаимодействия двух устройств:

1. когда отправитель готов отправить данные, он устанавливает сигнал valid
2. когда приемник готов принять данные, он устанавливает сигнал ready
3. отправитель считает данные переданными, если в одном такте с valid установлен сигнал ready
4. приемник, если установлен ready и принимается valid, обязан (!) принять данные

Пример со стороны передатчика:

```
clk:      __|^^|__|^^|__|^^|__|^^|__
valid_o:  ___|^^^^^^^^^^^^^^^^|_____
data_o:   ___|AAAAAAAAAA|BBBBB|_____
ready_i:  _________|^^^^^^^^^^^^|___
                        %     %

% := данные переданы
```

### Valid-Credit

Более гибкий, но тем не менее простой, интерфейс взаимодействия двух устройств

1. отправитель имеет некоторый счетчик, который содержит число так называемых кредитов — количество отправлений данных, которые он может совершить без всякого подтверждения от приемника за один такт
2. приемник согласован с отправителем, т.е. он гарантирует, что, если отправитель не будет превышать количество отправлений больше, чем число доступных кредитов, он обязуется принимать все отправления
3. каждый раз, когда отправитель отправляет данные — он затрачивает один кредит
4. каждый раз, когда приемник обрабатывает одни входящие данные и освобождает свои ресурсы — он выдает отправителю обратно один кредит
5. если у отправителя закончились кредиты, он обязан прекратить передачу и ждать возвращения кредитов от приемника
6. важный момент: отправитель, принимая входящий кредит от приемника, может тут же его использовать! иногда такое запрещено, зависит от конкретной реализции

Пример со стороны передатчика (для простоты: случай, когда входящий кредит нельзя использовать сразу, только со счетчика):

```
clk:      __|^^|__|^^|__|^^|__|^^|__|^^|__
valid_o:  ___|^^^^^^^^^^|______|^^^^|_____
data_o:   ___|AAAA|BBBBB|______|CCCC|_____
cntr:     22222222|11111|00000|11111|00000
credit_i  ________________|^^^|___________
                  %     %           %

% := данные переданы
```

## Описание модуля

Часто встречаются случаи, когда модуль-отправитель работает по протоколу Valid-Ready, а модуль-приемник по протоколу Valid-Credit! В данном случае появляется необходимость "подружить" эти модули, не прибегая к изменению их внутренностей — для этого используются преобразователи интерфейсов подобно нашему

Суть, преобразователь привносит недостающий счетчик кредитов для модуля-отправителя, выдавая в сторну модуля-отправителя сигнал ready, подтверждающий, что данные действительно можно считать переданными

В нашей реализации преобразователь может использовать входящий сигнал сразу в том же такте (!)

Полное количество кредитов после сброса сразу находится на стороне отправителя

Количество кредитов: 2

### Интерфейс

| имя | ширина | направление | комментарий |
| --  | --     | --          | --          | 
| clk      | 1 | input  | тактовый сигнал           |
| rst_n    | 1 | input  | сброс (инвертированный)   |
| valid_i  | 1 | input  | valid от модуля-отправителя  |
| ready_o  | 1 | output | ready для модуля-отправителя  |
| valid_o  | 1 | output | valid для модуля-приемника  |
| credit_i | 1 | input  | credit от модуля-приемника  |

## Свойства

| идентификатор | описание |
| -- | -- |
| h0 | преобразователь не может произвольно установить valid_o, если нет valid_i |
| h1 | преобразователь сохраняет корректность данных при передаче, если установлен valid_o |
| h2 | если преобразователь установил ready_o, то при наличии valid_i передача данных гарантировано происходит |
| h3 | если преобразователь получает кредит, то при наличии valid_i он обязан им воспользовать для передачи данных |
| h4 | если в прошлом такте был получен кредит, и им не воспользовались, то в текущем такте, даже если нет входящего кредита, при наличии valid_i преобразователь обязан передать данные |
| h5 | количество кредитов в системе меньше или равно двум |
